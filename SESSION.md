# Отчёт о сессии: приложение «МойРобот» (BraavaLocal)

Краткая история разработки Android-приложения для **локального управления роботом
iRobot Braava Jet m6** (в обход облака) и все находки по протоколу и телеметрии.

- **Приложение:** «МойРобот» (внутреннее имя проекта `BraavaLocal`)
- **Пакет:** `com.braava.local`
- **Стек:** Kotlin + Jetpack Compose, Gradle 8.11.1 / AGP 8.7.3 / Kotlin 2.0.21
- **Репозиторий:** https://github.com/031168-sudo/iRobot
- **APK:** https://gmpony.alfanomy.ru/apk/braavalocal-debug.apk (basic-auth как у веб-интерфейса)

---

## 1. Что делает приложение

- **Мастер настройки** (2 способа):
  - «Аккаунт iRobot» — вход в облако, получение BLID + локального пароля робота.
  - «Вручную» — BLID/пароль/IP + получение пароля с робота в режиме прослушивания (кнопка HOME).
- **Мультироботность**: список сохранённых роботов, выбор активного (⚙ — управление роботами),
  удаление. Старый одно-роботный формат настроек мигрируется автоматически.
- **Обнаружение** робота в сети (UDP-бродкаст `irobotmcs`, порт 5678).
- **Локальный MQTT** (TLS 8883) — команды и телеметрия.
- **Управление:** Убрать / Пауза / Далее (resume) / Стоп / Домой / Найти.
- **Статус и телеметрия:** фаза, заряд, салфетка, бак, ошибки, готовность, «Датчики за миссию».
- **Настройки уборки** (все локально, через `delta`).
- **Здоровье**: батарея, пробег, миссии, зарядки, перезагрузки, навигация, устройство.
- **Карты из облака**: список планов, покрытие комнат, переименование, уборка по комнатам.
- **История уборок** из облака: список миссий, карта уборки, привязка к карте/комнатам.
- **Диагностика** подключения (TCP/TLS) и **журнал обмена** (входящие/исходящие сообщения).

## 2. Протокол: облако

### 2.1 Вход и регионы
- Discovery: `GET https://disc-prod.iot.irobotapi.com/v1/discover/endpoints?country_code=<CC>`.
- Gigya: `POST {gigya}/accounts.login` (`apiKey`, `targetEnv=mobile`, `loginID`, `password`).
- iRobot: `POST {httpBase}/v2/login` (`app_id=ANDROID-C7FB240E-...`, `gigya{signature,timestamp,uid}`).
- **Региональность:** для `country_code=RU` discovery возвращает **другой Gigya-ключ и датацентр `eu1.gigya.com`**;
  для остальных — `us1`. Аккаунт живёт на одном сайте, поэтому вход нужно пробовать по регионам (RU→US).
  Иначе Gigya отдаёт `403042 invalid loginID or password` даже при верных данных.
- `/v2/login` возвращает `{robots:{blid:{password,...}}, credentials:{AccessKeyId,SecretKey,SessionToken}}` —
  временные AWS-креды для облачного data-API.

### 2.2 Облачный data-API (AWS SigV4)
- Подпись SigV4 (service `execute-api`, регион из deployment, обычно `us-east-1`), хост — `httpBaseAuth`.
- Эндпоинты:
  - `GET /v1/{blid}/pmaps?visible=true&activeDetails=2` — сохранённые карты (планы) + комнаты.
  - `GET /v1/{blid}/pmaps/{pmap_id}/versions/{pmapv_id}/umf?activeDetails=2` — геометрия (слои `coverage`, `coverage_poly`).
  - `GET /v1/{blid}/missionhistory?...&count=100` — история уборок.
- **Проблема DNS:** на некоторых сетях/VPN хост `auth2...` не резолвится — реализован перебор
  хостов API (`auth2`→`unauth2`→`auth1`→`auth3`).

## 3. Протокол: локальный MQTT

- Транспорт: MQTT 3.1.1 / TLS, порт **8883**; `clientId = username = BLID`, пароль — локальный.
- Подписка `#`, команды публикуются в топик `cmd`, настройки — в `delta`.
- **Критичные особенности, найденные в бою:**
  - Робот самоподписанный и со слабым TLS → нужен trust-all и **только RSA-шифры** (без DHE).
  - Paho создаёт сокет через **`createSocket()` без параметров** — его обязательно реализовать в SSLSocketFactory
    (иначе `Unconnected sockets not implemented`).
  - Робот принимает **одно** локальное соединение и может кратко отказывать при закрытии старой сессии →
    автоповтор подключения с backoff.
  - Команды нужно слать с **QoS 0** (на QoS 1 брокер не подтверждает, и команда не применяется).

## 4. Телеметрия m6: что реально есть

- **`pose` (позиции) локально НЕТ** — ни на базе, ни в движении, хотя `cap.pose=2`. Карта/позиция
  строятся на роботе (vSLAM) и уходят только в облако. Трек локально не построить.
- **`cleanMissionStatus.mssnM` не тикает** (0 во время уборки) — время миссии считаем локально по `mssnStrtTm`.
- **`notReady`** — не битовая маска, а **индекс причины** (73 значения): «Нет салфетки», «Мало воды», «Контейнер полон» и т.д.
- **Ошибки** — `cleanMissionStatus.error` (есть каталог кодов). Пример: без салфетки → ошибка/`notReady`.
- **`tankLvl` — бинарный датчик** (не проценты): 100 = вода есть (выше датчика), 0 = пусто.
- Счётчики (растут в реальном времени): `bbswitch.nBumper`, `bbrun.nStuck/nPanics/nCliffsF` и др. —
  показываем как «Датчики за миссию» (дельта от старта).
- `rankOverlap`, `padWetness`, `chrgLrPtrn` — это настройки (см. ниже), а не «шум».

## 5. Настройки m6 (все локально через `delta`)

| Настройка | Значения | Поле |
|---|---|---|
| Проходы | Один / Два / Авто | `noAutoPasses`, `twoPass` |
| Количество жидкости | Эко=1 / Стандарт=2 / Ультра=3 | `padWetness{disposable,reusable}` |
| Индикаторы состояния | Заряд+док=0 / Док=1 / Выкл=2 | `chrgLrPtrn` |
| Перекрытие траектории мытья | Малое=25 / Среднее=67 / Большое=85 | `rankOverlap` |

**Убрано как нелегитимное для m6:**
- «Убирать по периметру» (`openOnly`) — `cap.edge=0`.
- «Всегда доводить до конца» (`binPause`) — робот поле не присылает.

Методика проверки: меняем настройку в iRobot-приложении → присылаем телеметрию → сопоставляем число.

## 6. Карты и история (облако)

- **`pmaps`** — сохранённые планы (у пользователя 6). `create_time` — дата создания плана, поэтому «старые».
- **История уборок** — `missionhistory`; каждая запись ссылается на `pmap_id`/`pmapv_id` и содержит дату,
  результат, длительность, площадь (`sqft`, показываем в м²). Это соответствует «Истории» в приложении.
- Уборка **не создаёт новую карту** — она дорисовывает покрытие на существующей версии плана.
- Реализовано:
  - кэш карт/истории на устройстве (**просмотр без входа**, сеть — только по кнопке «Обновить»);
  - отрисовка покрытия (`coverage`) и контуров комнат (`coverage_poly`);
  - **«Карты» показывают объединение покрытия по всем сохранённым уборкам** этого плана (из локального кэша),
    а не только последнюю (часто частичную) версию;
  - **переименование карт и комнат** (локально);
  - **уборка по комнатам**: команда `start` с `regions:[{region_id, type:"rid"}]` (локально);
  - в истории подтягиваются **название карты и комнат** (с учётом переименований).

## 7. UX / прочие решения

- Мультироботность и шестерёнка возврата к списку.
- Логин в окнах карт/истории спрятан за кнопку «Обновить».
- Выбор карты/уборки открывает **отдельное окно**.
- Кнопки выбора настроек компактные (без переноса слов).
- Иконка: нарисованная (векторная) «мультяшная» иконка робота-поломойки; название — **МойРобот**.

---

## 8. Известные ограничения

- Управление и телеметрия — **без карты** (m6 локально карту не отдаёт).
- Уборка по комнатам зависит от того, вернуло ли облако `regions`, и от поддержки `regions` прошивкой.
- Переименования — локальные (облако/приложение iRobot не изменяются).
- Карта/история требуют входа в облако (VPN); после первого раза работают из локального кэша.
- Команда `dock` — приоритетная, `stop`/`pause` её на m6 не сбивают (помогает кнопка на роботе или `start`).
