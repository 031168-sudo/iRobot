# Передача проекта «МойРобот» (BraavaLocal)

Точка входа для продолжения на **другом сервере / в другой сессии OpenCode**.
Глубокие детали протокола — в `SESSION.md`, правила проекта — в `AGENTS.md`.

- **Репозиторий:** https://github.com/031168-sudo/iRobot
- **Версия:** 2.8 (`versionCode 19`), ветка `master`.
- **Что нового в 2.8:** поддержка локального управления Xiaomi-пылесосом
  (`roborock.vacuum.m1s`): вход в Mi-аккаунт, получение miIO-токена, статус,
  базовые команды и **уборка по комнатам** (`app_segment_clean`). Карта
  остаётся в облаке Xiaomi. Плюс всё из 2.7 (бесконечный ретрай и т.д.).
- **Сборка:** только GitHub Actions; локальная публикация APK больше не используется.

## Что это

Android-приложение «МойРобот» для **локального управления iRobot Braava Jet m6**
по Wi-Fi, в обход облака:

- локальный **MQTT 3.1.1 поверх TLS**, порт **8883**;
- обнаружение — **UDP 5678**, broadcast `irobotmcs`;
- нужны **BLID + локальный пароль** робота;
- облако iRobot используется только для получения пароля, карт и истории
  (для РФ нужен VPN).

Стек: Kotlin + Jetpack Compose, Gradle 8.11.1, AGP 8.7.3, Kotlin 2.0.21,
minSdk 26, target/compileSdk 35.

## Что сделано в этой сессии

- **v2.4 (versionCode 15)** — автовосстановление IP при смене DHCP:
  UDP-broadcast, TCP-скан подсети по 8883 и unicast-проба `irobotmcs` по BLID;
  версия приложения показывается в меню.
- **v2.5 (16)** — вход в iRobot сохраняется зашифрованным (AES/GCM, ключ в
  AndroidKeyStore, шифртекст в SharedPreferences); формы входа автозаполняются;
  в меню есть «Забыть пароль iRobot».
- **v2.6 (17)** — «Убрать выбранные» работает как favorite:
  отправляются `pmap_id`, `user_pmapv_id`, `regions` и текущие настройки
  (`noAutoPasses`, `twoPass`, `padWetness`, `rankOverlap`).
  Версия выбирается так: облачная пользовательская (`user_pmapv_id`) →
  локальная с робота (`reported.pmaps`) → активная. Источник показывается
  в статусе. «Убрать всё» в окне карты тоже стартует с закреплённой версией.
  Главная кнопка «Старт» осталась обычным `start`.
- **v2.7 (18) — надёжное подключение.** Причина жалобы «приложение не видит
  робота» разобрана 20–21.11.2026:
  - робот периодически выпадает из Wi-Fi на 10–60 с; в это время телефон
    получает `EHOSTUNREACH` (ARP не проходит), discovery пустой, TCP не идёт,
    а облачное приложение продолжает показывать последнее состояние;
  - локальный пароль в приложении может устареть (после перепривязки/сброса):
    сеть в порядке, TLS проходит, но брокер отвечает `CONNACK 4`
    «Неверный BLID или пароль». Лечится повторным получением пароля из облака
    («Аккаунт iRobot» → «Получить доступ к роботу») или с робота в режиме
    прослушивания;
  - изоляция клиентов на Xiaomi проверялась и **опровергнута**: с сети
    `186-24` приложение подключается, `TLS: OK`;
  - робот держит **одно** локальное MQTT-соединение, частые TCP-пробы
    (каждые 5 с) могут ему мешать — не спамить проверками.
  - Что изменено в коде: бесконечный ретрай с backoff (1.5–15 с) и периодический
    автопоиск вместо «3 попытки и стоп»; остановка на неверном пароле с
    подсказкой; понятные ошибки сети; ECDHE первым, RSA запасным; TCP-скан
    600 мс в два прохода; кнопка «Подключиться к IP…».
- **v2.8 (19) — Xiaomi (miIO).** Добавлена поддержка Xiaomi-пылесоса
  (`roborock.vacuum.m1s`):
  - вкладка **«Xiaomi»** в мастере: вход в китайский Mi-аккаунт, получение
    списка устройств и miIO-токена, выбор робота и IP;
  - локальный слой `data/xiaomi/MiioClient.kt`: UDP 54321, AES-128-CBC,
    рукопожатие, `get_status`, `get_room_mapping`, `app_segment_clean`,
    `app_start/stop/pause/charge`, `find_me`;
  - отдельный экран управления: статус, заряд, время/площадь уборки, комнаты
    с кнопкой «Убрать»;
  - `RobotConfig` получил `kind` (`IROBOT`/`XIAOMI`) и `token`; iRobot-репозиторий
    не пытается подключиться по MQTT к Xiaomi-роботу.
  - карта Xiaomi остаётся в облаке: `get_map_v1` — только указатель, файл
    с `api.io.mi.com`; локально карты нет.
- Разобрано: `notReady=68` — это «Карта недоступна», а не «Загрузка карты».
- Проверено: `train` создаёт новые версии карты, но не делает их активными;
  промоушен `active_pmapv_id` — на стороне облака/нативного приложения.

## Сборка: только в GitHub

Канонический путь — GitHub Actions:

1. push в `master` (или ручной `workflow_dispatch`);
2. workflow **Build APK** `.github/workflows/android.yml`;
3. JDK 17 + предустановленный Android SDK на `ubuntu-latest`;
4. `./gradlew :app:assembleDebug`;
5. артефакт **`braavalocal-debug-apk`** с файлом `app-debug.apk`.

Постоянная ссылка — GitHub Release (workflow **Release APK**
`.github/workflows/release.yml`, запуск на тег `v*` или вручную):

- `https://github.com/031168-sudo/iRobot/releases/download/v2.7/MyRobot-2.7.apk`
- тег создаётся под версию из `app/build.gradle.kts` (`v2.7` и т.д.);
- рядом с релизом можно скачать `app-debug.apk` из артефактов run.

Скачать APK из CI:

- GitHub → **Actions** → последний run → **Artifacts** →
  `braavalocal-debug-apk`;
- или `gh run download -n braavalocal-debug-apk`.

На новом сервере достаточно клонировать репозиторий. `local.properties`,
`.gradle/` и `app/build/` в git нет — они не нужны: CI сам находит SDK.

Старая локальная публикация APK на прежнем сервере — только историческая;
на новом сервере её нет.

## Что не лежит в GitHub (и не должно)

- `local.properties` (путь к Android SDK), `.gradle/`, `app/build/` —
  генерируются локально.
- APK/AAB — не коммитятся, собираются в CI.
- Логин iRobot и локальный пароль робота — только на телефоне, в зашифрованном
  виде; в репозитории их нет.
- `keystore/debug.keystore` — **намеренно в репозитории**, ключ публичный
  (`androiddebugkey` / `android`), чтобы CI и локальные сборки давали одинаковую
  подпись и обновления ставились поверх.
- Никаких `.env`, токенов, ключей серверов и паролей в репозитории нет.

## Ограничения и открытые вопросы

1. **Подключение.** Discovery может находить робота по BLID, но TCP 8883 или
   MQTT-коннект может не проходить. Частые причины: занято единственное
   локальное MQTT-соединение, AP/client isolation, VPN или Private DNS на
   телефоне, закрытый порт, устаревший пароль после factory reset.
   В приложении: **⋮ → «Диагностика подключения»** (TLS/TCP). С ноутбука:
   `nc -vz <ip> 8883`.
2. **Уборка по комнатам.** Версия карты берётся из облака (`user_pmapv_id`),
   иначе локальная, иначе активная; в статусе видно источник. Если облачный
   кэш старый, `user_pmapv_id` может быть пустым — нужно обновить карты (VPN).
3. **Карты.** Не редактировать и не переименовывать карту в нативном приложении
   iRobot: это триггерит зависание «Сохранение точной карты». Смотреть — можно.
4. **Рабочий сценарий.** Занести робота в комнату, закрыть дверь, нажать Start
   (или кнопку на роботе) — карта строится. Это основной путь; локальное
   «переобучение карты» не требуется.
5. **Идеи на будущее:** кнопка Spot; локальный экран карт (`pmaps`); привязка
   `pmap_id` + `user_pmapv_id` в главный Start (сейчас только room clean и
   «Убрать всё»).

## Как продолжить в новой сессии

1. Клонировать репозиторий и открыть его каталог в OpenCode.
2. Прочитать `AGENTS.md`, этот файл и `SESSION.md`.
3. Сборка — через GitHub Actions. Локально — только если есть Android SDK.
4. Коммит/пуш — по явной команде пользователя.
